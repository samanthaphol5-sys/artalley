# Art Alley — ตลาดงานศิลปะและงานจ้างวาด

เวอร์ชันนี้ตรงกับ prototype ล่าสุด (Art Alley): ดีไซน์ใหม่, สลับภาษา TH/EN, ตะกร้าและคำสั่งซื้อ (งานวาดมือ/งานดิจิทัล),
หน้าสินค้าแบบเต็ม + รีวิว, ติดต่อศิลปิน (กล่องข้อความ), การจัดส่งที่ศิลปินตั้งเอง, ระงับบัญชีและ "เข้าใช้ในฐานะ" สำหรับแอดมิน

**ใหม่ในเวอร์ชันนี้ (เทียบกับ Shatter v2)**
- เปลี่ยนชื่อเป็น Art Alley (ฐานข้อมูลชื่อ `artalley`, อีเมลตัวอย่าง `@artalley.local`)
- 1 อีเมลมีได้ 2 โปรไฟล์ (ลูกค้า + ศิลปิน) ใช้รหัสผ่านเดียวกัน สลับหรือสร้างอีกโปรไฟล์ได้ในหน้า "บัญชีของฉัน"
- ลืมรหัสผ่าน / ตั้งรหัสผ่านใหม่ (ลิงก์ใช้ได้ครั้งเดียว อายุ 30 นาที)
- ผลงานมีได้หลายรูป (1–8 รูป เรียงลำดับได้ รูปแรกเป็นภาพปก)
- ศิลปินมีรูปปกหน้าโปรไฟล์ · ตั้งค่าสตูดิโอย้ายไปรวมในหน้า "บัญชีของฉัน"
- แท็ก "อื่น ๆ" ทั้งสไตล์และหัวข้อ
- ผู้เยี่ยมชมเห็นทุกอย่างเหมือนลูกค้า แต่กดซื้อแล้วต้องเข้าสู่ระบบก่อน (ระบบใส่ตะกร้าให้ต่อหลังเข้าสู่ระบบ)

## วิธีรัน

1. **ฐานข้อมูล** — MySQL Workbench → เปิด `db/schema.sql` กด ⚡ แล้วเปิด `db/seed.sql` กด ⚡
   (schema.sql ลบฐานข้อมูล `artalley` เดิมแล้วสร้างใหม่ · ฐานข้อมูล `shatter` ของเวอร์ชันก่อนไม่ถูกแตะ ลบเองได้ถ้าไม่ใช้แล้ว)
2. **ตั้งค่า** — ใน `backend/` คัดลอก `.env.example` เป็น `.env` แล้วแก้ `DB_PASSWORD`
   (ถ้าคัดลอก `.env` มาจากเวอร์ชันก่อน ให้เปลี่ยน `DB_NAME=shatter` เป็น `DB_NAME=artalley`)
3. **รัน**
   ```bash
   cd backend
   npm install
   npm start
   ```
4. เปิด **http://localhost:3000**

## หลักการทำงาน (สำหรับคนที่จะแก้โค้ดต่อ)

- หน้าเว็บโหลดข้อมูลทั้งหมดที่ผู้ใช้มีสิทธิ์เห็นจาก `GET /api/state` ครั้งเดียว แล้วสร้างหน้าจากข้อมูลนั้น
- ทุกการกระทำ (ใส่ตะกร้า, ส่งข้อความ ฯลฯ) เรียก API เฉพาะเรื่อง → backend ตรวจสิทธิ์และบันทึก → หน้าเว็บโหลด `/api/state` ใหม่
- **การตรวจสิทธิ์ทั้งหมดอยู่ที่ backend** หน้าเว็บซ่อนปุ่มเพื่อความสะดวกเท่านั้น
- ราคาในคำสั่งซื้อ backend คำนวณเองจาก `utils/pricing.js` ไม่เชื่อราคาที่หน้าเว็บส่งมา
- รูปอ้างอิงและสเก็ตช์งานจ้างเป็นไฟล์ส่วนตัว โหลดผ่าน API ที่ตรวจว่าเป็นคู่สัญญาเท่านั้น ไฟล์ดิจิทัลที่ขายก็ดาวน์โหลดได้เฉพาะคนที่ซื้อแล้ว
- การกระทำของแอดมิน (ระงับบัญชี, เข้าใช้ในฐานะ ฯลฯ) ถูกบันทึกในตาราง `admin_audit`
- **บัญชีกับโปรไฟล์:** ตาราง `accounts` เก็บอีเมล+รหัสผ่าน, ตาราง `users` คือโปรไฟล์ (ลูกค้า/ศิลปิน/แอดมิน) ที่ผูกกับบัญชี
  ทุกอย่างอื่น (ผลงาน ออเดอร์ งานจ้าง) ผูกกับโปรไฟล์ · การระงับก็ระงับเป็นรายโปรไฟล์
- **ลืมรหัสผ่าน:** ยังไม่ได้ต่อระบบส่งอีเมล ลิงก์ตั้งรหัสผ่านใหม่จะพิมพ์ใน terminal ที่รัน `npm start`
  และหน้าเว็บจะโชว์ลิงก์เป็น "อีเมลจำลอง" ให้ (เฉพาะตอน `NODE_ENV` ไม่ใช่ `production`) ถ้าจะใช้จริงให้ต่อระบบส่งอีเมลใน `routes/auth.js` ตรง `/auth/forgot`

**ข้อจำกัดที่ควรรู้:** การโหลดข้อมูลทั้งหมดผ่าน `/api/state` เหมาะกับโปรเจกต์สาธิตที่ข้อมูลไม่เยอะ
ถ้าข้อมูลโตขึ้นมาก ควรแยกเป็น API ต่อหน้าและแบ่งหน้า (pagination) · การชำระเงินยังเป็นแบบสาธิต ไม่ตัดเงินจริง ·
ยังไม่มีลืมรหัสผ่านทางอีเมล

## ปัญหาที่พบบ่อย

- **หน้าเว็บขึ้น "เชื่อมต่อเซิร์ฟเวอร์ไม่ได้"** — ยังไม่ได้รัน `npm start` หรือเปิดไฟล์ HTML ตรง ๆ (ต้องเปิดผ่าน http://localhost:3000)
- **`Access denied for user 'root'`** — รหัสผ่านใน `backend/.env` ไม่ตรง
- **`Unknown database 'artalley'`** — ยังไม่ได้รัน `db/schema.sql` หรือ `DB_NAME` ใน `.env` ยังเป็นชื่อเก่า
- **`Port 3000 is already in use`** — เปลี่ยน `PORT` ใน `.env`
- **ดูว่า API ตอบอะไร** — กด F12 → แท็บ Network
